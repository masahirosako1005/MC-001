# ADR 0009: スポットの公開期間・GPS によるカメラ起動判定・シークレットシンボル

- 状態: 採用
- 日付: 2026-11-09

## 背景

運営がシンボルを置くスポットを自分で追加・編集・削除でき、期間限定のスポット(イベントなど)も作りたい。
また、シンボルがない場所でカメラを起動しても何も起きないため、近くにシンボルがあるときだけカメラを起動させたい。
地図上では「ここで手に入るコーデ」を事前に見せて再訪のきっかけにしつつ、シークレットシンボルは中身を伏せたい。

## 決定

### スポットの公開期間
- `Spot.starts_at`(公開開始)/`Spot.expires_at`(有効期限)。**どちらも空欄なら無期限**。DB の CHECK 制約で「期限 > 開始」を保証
- 「探せるスポット」は `spot_available_q()` に集約: 公開中 かつ 開始済み かつ 期限前。スポット一覧・地図・QR / 画像の読み取り・受け取り・近くのシンボル判定・コーデ画像のすべてがこれを通るので、**期限が切れた瞬間にどこからも見えなくなる**(バッチ処理は不要)
- 管理画面 `/explore/manage/spots/`(スタッフのみ): 追加・編集(地図をクリック / ピンをドラッグして位置を設定、判定半径を円で表示、「無期限にする」チェック)・削除
- **削除は利用者の記録(訪問・みっけ履歴)がないときだけ**。記録があるスポットは「非公開にする」か「今すぐ期限切れにする」を選ぶ(履歴やコレクションを壊さない)。すべての操作は監査ログに残す

### GPS によるカメラ起動判定
- `SiteSetting.camera_radius_m`(既定 100m、10〜5000m)。管理画面「共通 > サイト設定」で変更できる
- カメラ画面で「カメラをはじめる」/「写真から読み取る」を押すと、端末の位置を `POST /explore/api/nearby` に送り、周囲にシンボルがあればカメラを起動。なければ **「ここにはなさそう・・・」** といちばん近いスポットまでの距離を表示し、起動しない
- シンボルの位置は `Symbol.latitude/longitude`(任意、管理画面の「シンボル」で設定)。未設定ならスポットの位置を使う
- **位置情報は URL に載せない(POST 本文)・保存しない・ログに出さない**。レート制限 30 回/分。判定結果は端末で 60 秒だけ覚え、その間は再判定しない
- 管理者はテスト用に「位置の確認を省略する」を選べる(一般利用者には表示しない)
- これは利便性のための入口判定で、不正対策ではない(位置は偽装できる)。現地確認が必要なスポットは従来どおり受け取り時に `require_location` で判定する

### 地図で「ここで獲得可能なコーデ」を見せる
- スポット地図の「近くのシンボルを探す」で、周囲のシンボルを★マーカーで表示。タップするとポップアップに**手に入るコーデの画像**(着ている姿のプレビュー)と条件(「秋限定」「夜だけ」「2日目の訪問から」など)を表示。今の季節・時間帯では出ないものは薄く表示
- 画像は `/explore/symbols/<id>/items/<code>.svg`。そのシンボルのドロップに含まれるアイテムだけを返す(任意のアイテムを覗けない)
- 地図を操作しにくい人向けに、同じ内容をボタンの一覧でも開ける

### シークレットシンボル
- `Symbol.is_secret`。画像シンボル登録画面と管理画面で設定
- 地図では「?」マーカーと**「？」の画像**(`static/img/secret.svg`)だけを表示。API の応答にも名前・ヒント・アイテムを**含めない**(画面で隠すだけでなくデータとして渡さない)。コーデ画像の URL も 404
- スポット一覧では、本人が一度みっけするまで「？？？(シークレットシンボル)」と表示

### 追記: 「みっけ」と「スポット」の統合(2026-11-09)
- スポットが分からないとカメラを起動できないため、**地図(さがす)とカメラ(みっけ)を 1 画面 `/explore/` に統合**。「みっけに行く」・メニューの「みっけ」はここを開く。メニューの「スポット」は廃止
- 画面を開くと、まず **①現在地の取得 → ②周囲のシンボル検索** を順番に行う(`static/js/nearby.js`)。地図の「現在地」と「近くのシンボルを探す」も同じ処理を呼ぶ。実行中に押されても二重には走らない
- 近くにシンボルがあると分かるまで「カメラでみっけ」「写真から読み取る」は押せない(サーバーから返った HTML の時点で disabled)。確認から 3 分以内ならカメラ起動時に再検索しない
- カメラは同じ画面で開き、「地図にもどる」で ① にもどる。カメラが使えないときは理由を地図の上に出す
- 地図・カメラは `mikke:nearby` イベントで検索結果を受け取る(位置の取得・API 呼び出しは nearby.js の 1 か所だけ)
- スポットのカード一覧はいったん非表示(`SHOW_SPOT_CARDS = False`。テンプレートは `explore/_spot_cards.html` に残してある)。旧 `/explore/camera/` は 301 で `/explore/` へ
- 画面を開いた時点で位置情報の許可を求めることになるが、「みっけに行く」を押した直後なので利用者の意図に沿う。拒否された場合は理由と再試行の方法を表示する

## トレードオフ

- 近くのシンボル判定は公開中のシンボルを全件読み込んで距離を計算している(数百件までを想定)。大規模になったら緯度経度の範囲で絞り込む、または PostGIS を使う
- 位置情報の精度が悪い屋内などでは、近くにいても「ここにはなさそう」になることがある(判定距離を広げて調整する)
- 期限はスポット単位。シンボル単位の期限は未対応

# ADR 0001: みっけシンボルの検出方式

- 状態: 採用
- 日付: 2026-11-09

## 背景

「カメラ経由でシンボル(画像)を検知し、映像上に印を出す」必要がある。候補は次の3つ。

| 方式 | 長所 | 短所 |
|---|---|---|
| A. 任意画像の自然特徴追跡(MindAR 等) | 自由なイラストを使える | 事前コンパイル・重い処理、古い端末で不安定。ライブラリ API の検証コストが高い |
| B. ArUco 等の専用マーカー | 高速・頑健 | 見た目が無機質。追加ライブラリ |
| C. QR コード(誤り訂正 H)+ 中央ロゴ + 装飾枠 | 軽量・頑健、jsQR は依存なし、四隅座標が取れ AR マークを追従できる | 見た目の自由度は中程度 |

## 決定

**C を採用**。`explore/symbols.py` が「みっけシンボル」SVG を生成する(QR + 中央「み」ロゴ + スポット名入りの枠)。中身は `MIKKE1:<推測不可能なトークン>` で、URL や個人情報は含まない。

- 検出: ブラウザ内で jsQR 1.4.0(npm の integrity `sha512-dxLob7q…` を照合して同梱)
- 映像フレームはサーバーに送らない(プライバシー・通信量)
- 不正対策: 受け取りは「サーバー署名付き・利用者紐付け・5分有効」のチケット経由。シンボルごとのクールダウン。スポット単位で位置情報による現地確認を ON にできる

## 結果・トレードオフ

- 一般のカメラアプリでも文字列は読めるが、URL ではないため外部サイトに誘導されない
- シンボルの写真を SNS で共有されると遠隔取得が可能 → 現地確認(位置情報)をスポット単位で有効化して抑止。位置偽装は完全には防げない(残存リスク)
- 将来、任意イラストの認識が必要になった場合は A を追加方式として検討(撤退しやすいよう検出部分は `camera.js` の `detect()` に閉じている)

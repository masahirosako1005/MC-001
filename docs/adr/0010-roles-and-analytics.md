# ADR 0010: 権限の分離(利用者・管理者・サイト運営者)と運営向け分析

- 状態: 採用
- 日付: 2026-11-09

## 背景

これまでは「運営スタッフ (is_staff)」と「利用者」の 2 種類だけだった。店舗・会社がそれぞれ自分のスポットとシンボルを登録できるようにし、サイト全体の運営 (利用者管理・分析) は別の権限に分けたい。
運営者は、スポットごとに「付近に来た人 → カメラを起動した人 → コーデを獲得した人」と利用割合を、時間帯・季節別に見たい。

## 決定

### 3 つの権限 (`User.role`)
| 権限 | できること | 登録・退会 | ログイン |
|---|---|---|---|
| 利用者 `user` | みっけ・着せかえ・コンテスト | 自分で登録・自分で退会 | 通常のログイン |
| 管理者 `manager` | **自分が担当のスポット**とそのシンボル (QR 追加・画像撮影登録・設定・ドロップ) | サイト運営者が追加 (仮パスワードを 1 度だけ表示し、最初のログインで変更を強制) | 通常のログイン |
| サイト運営者 `operator` | 利用者管理 (追加できるのは管理者だけ・停止/再開)・分析・すべてのスポット・Django 管理画面 | Django の createsuperuser / 管理画面 | **専用のログイン画面** `MIKKE_OPS_URL` |

- `is_staff` は role から自動で決まる (サイト運営者だけ True)。is_superuser はサイト運営者にしか持たせない (DB 制約)
- 既存の運営スタッフ (test@test.com など) はマイグレーションでサイト運営者に移行
- 管理者の基本情報 `ManagerProfile`: 管理者 ID (`MK-` + 紛らわしい文字を除いた 6 文字、自動採番)、会社・団体名、店舗・施設名、業種、担当者名、郵便番号、**住所・電話番号 (暗号化)**、Web サイト、運営メモ
- スポットに「担当の管理者」(`Spot.owner`) を追加。管理者が作ったスポットは自動で本人の担当。サイト運営者は担当を割り当てられる
- 権限の確認は `core/permissions.py` に集約 (`manager_required` / `operator_required` / `managed_spots`)。管理者が他店のスポット・シンボルの URL を直接開いても 404
- 運営画面は、運営者以外のログイン中の人には 404 (存在を見せない)、未ログインなら専用ログインへ

### ログインの分離
- 通常のログインは利用者・管理者だけ。運営者のアカウントで入ろうとしても「メールアドレスまたはパスワードが違います」と同じ文言で断る (運営者のアカウントかどうかを明かさない)
- 運営者のログインは URL を `.env` で変えられる。失敗の上限を半分にし、ロック時間を 2 倍、ログインの有効時間を 4 時間 (設定可) にする。Django 管理画面のログインは運営者ログインに転送
- これだけで攻撃を防げるわけではないが、入口を分けることで「どの URL に運営者がいるか」の手がかりを減らし、利用者向けと別の制限をかけられる

### 退会
- 利用者は「アカウント」から、パスワードと確認のチェックで退会できる。記録・アイテム・クーポン・コンテスト参加はすべて削除 (監査ログには ID だけ残す)
- 管理者・運営者はここから退会できない (運営者が停止する)

### 分析 (`/ops/`)
- **付近に来た** = 「近くのシンボルを探す」でそのスポットのシンボルが周囲にあったとき (`NearbyVisit`)。**座標は保存せず**、「どのスポットの付近に・いつ (日付・時間帯・季節) 来たか」と検索回数 (PV) だけを、人・スポット・日・時間帯ごとに 1 行にまとめる
- **カメラ起動** = カメラ (または写真読み取り) を起動したとき、直前 15 分以内に付近に来たスポットに数える
- **コーデ獲得** = みっけ (Discovery) のごほうびがアイテムだった人
- **利用割合 = コーデ獲得ユーザ数 ÷ 付近に来たユーザ数 × 100**。人数はすべて重複なし
- 絞り込み: 期間 (7/30/90/365 日・全期間)・季節・時間帯・管理者・並び順。グラフはスポット別 (上位 15)・時間帯別・季節別の棒グラフと利用割合、全スポットは表
- グラフはサーバーで SVG を組み立てる (CSP を緩めない・JS 不要)。系列色は色覚の違いでも区別できることを検証済みのパレット、凡例・マウスを乗せたときの値・表 (「表で見る」) を必ず付ける

### デモデータ (`python manage.py seed_analytics`)
- 架空のスポット 100 (シンボル約 130)、架空の管理者 12、仮想利用者 1,000 人、1 年分の行動 (付近の来訪・カメラ起動・みっけ)。スポットの種類ごとに時間帯・季節の傾向とランダムな人気をつけ、グラフに差が出るようにした
- 確認用アカウント: 管理者 manager@test.com、利用者 user@test.com (パスワードは test@test.com と同じ、DEBUG のときだけ作成)

## トレードオフ
- 分析は毎回その場で集計する (数万行までは 1 秒以内)。大規模になったら日次の集計テーブルを作る
- 「付近に来た」は、利用者が「近くのシンボルを探す」を使ったときにしか数えない (常時の位置追跡はしない: プライバシーを優先)
- 仮パスワードは画面に 1 度だけ表示する方式 (メール送信の仕組みがないため)。本番ではメールでの招待に置き換えるのが望ましい
- 管理者の退会・停止は運営者が行う。管理者を削除しても、スポットは残り「サイト運営者のスポット」になる

# ADR 0003: 再訪を促すゲーム設計(スタンプラリーとの差別化)

- 状態: 採用
- 日付: 2026-11-09

## 背景

スタンプラリーは「全部押したら終わり」で、再訪の動機が生まれにくい。

## 決定

1. **ドロップ表の条件**: `DropEntry` に `season`(春夏秋冬)・`time_slot`(朝/昼/夕/夜)・`min_visit_days`(n 日目の訪問から解放)を持たせ、重み付き抽選(`secrets.SystemRandom`)。同じシンボルでも「いつ・何回目に来たか」で中身が変わる
2. **クールダウン**: 同じシンボルは既定 20 時間後に再びみっけ可能(日帰り再訪・連泊で 2 回目が楽しめる)
3. **訪問日数・季節の記録**: `SpotVisit` を日本時間の日付単位で1件(一意制約)。実績「また来たよ」「常連さん」「四季めぐり」に使う
4. **成果が「身につく」**: 集めた物はアバターの服になり、旅の記憶が見える形で残る
5. **地域への還元**: クーポンは地元店舗と結びつけ、探索が消費につながる

## 測定(HEART [S12])

| 指標 | 測り方 |
|---|---|
| Retention | 同一スポットの `SpotVisit` が 2 日以上ある利用者の割合 |
| Engagement | 利用者あたりの `Discovery` 数 / 月 |
| Task success | スキャン成功 → 受け取り完了率(監査ログ `explore.collect`) |
| Adoption | 新規登録数(`account.signup`) |
| Happiness | 着せ替え保存回数(`avatar.update`)、将来アンケート |

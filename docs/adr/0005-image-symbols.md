# ADR 0005: 撮影した写真をシンボルにする「画像シンボル」

- 状態: 採用(ADR 0001 の QR 方式と併用)
- 日付: 2026-11-09(同日改訂: 四角形の切り抜き・塗りつぶしマスク・最大 9 角度・類似度 65% 判定)

## 背景

QR だけでなく、現地の看板・像・壁画などを**スタッフがカメラで撮影し、その写真をシンボルとして登録**したい。追加の要望:

1. 写真全体ではなく、**四角形で囲んだ部分だけ**をシンボルにする
2. 距離や角度は厳密でなくてよい。**近ければ一致(類似度 おおむね 65% 以上)**
3. 判定に使わない部分を**マウスで塗りつぶして除外**できる
4. 1 つのシンボルを**正面・右から・左から・斜め上から… 最大 9 角度**で登録できる

## 決定

### データ構造
`Symbol`(kind=image)1 件に対し、`SymbolView` を角度ごとに最大 9 件(左上/上/右上/左/正面/右/左下/下/右下。`(symbol, angle)` に一意制約)。各見え方が次を持つ:

| データ | 配布先 | 用途 |
|---|---|---|
| 切り抜き・正面補正した参照写真(JPEG) | スタッフのみ | 確認・撮り直し |
| ORB 特徴量(塗りつぶし部分の点を除く) | 利用者の端末 | 映像の中から探す |
| 32×32 照合用パッチ + 除外マスク(1024 ビット) | **サーバーのみ** | 本当に写っているかの確認 |

既存の 1 枚写真の画像シンボルは、マイグレーションで「正面」の見え方に移行した(元に戻すマイグレーションもあり)。

### 登録(`/explore/symbols/register/`、角度の追加・撮り直し・削除は `/explore/symbols/<id>/views/`)
1. 撮影(カメラ or 写真を選ぶ)
2. **四角形で切り抜き**: 4 つの角をドラッグ(キーボードの矢印キーでも可)。射影変換で正面から見た長方形に補正する(`MikkeImage.cropQuad`)
3. **塗りつぶし**: ブラシ(塗る/消す・大きさ変更・全消去)。塗った部分の特徴点を除き、照合用パッチのマスクにも反映。除外は最大 75%
4. 角度ごとに決定 → まとめて送信。サーバーは全角度を検証してから一括保存(1 件でも不正なら全体を巻き戻し、エラーに角度名を付けて返す)

### 認識(端末)
- jsfeat 0.0.8: YAPE06 特徴点 → ORB 記述子 → ハミング距離 + 比率テスト → RANSAC 射影変換 → **全正解点で射影変換を再計算**(精度向上)
- 参照画像は **6 段階の縮尺**、映像は **640px と 960px を交互**に走査して、遠くの小さなシンボルにも対応
- 特徴点は 4×4 の区画に分散して選ぶ(背景の模様に点を取られすぎない)
- 比率テストの「2 番目に近い点」は**別の位置の点だけ**で数える(複数縮尺に同じ点があるため)
- 正解とみなす条件は「RANSAC の一致点 10 点以上」(無関係な画像では偶然でも 4〜5 点)
- 追跡中のシンボルは全角度を優先して照合し、それ以外は 1 回に 3 件ずつ順番に照合

### 一致判定(サーバー、類似度 65%)
`image_symbols.similarity()`: 32×32 → 16×16 に粗くし、**上下左右 1 マス(約 6%)の位置ずれ**を許して正規化相互相関の最大値を取る。除外マスクの部分は使わない。登録された全角度のうち最も高い値が `MIKKE_IMAGE_SIMILARITY_THRESHOLD`(既定 0.65)以上なら一致。類似度の値そのものは利用者に返さない(総当たりの手がかりにさせない)。

## 検証結果(PC のブラウザ、合成した街の写真で各 4 回)

| ケース | 結果 |
|---|---|
| 近い(看板が画面幅の 45%) | 4/4 一致 |
| 登録時と同じ距離(31%)・暗い | 3/4 一致 |
| 遠い(20%)/さらに遠い(16%)※960px 走査 | 3/4 / 3/4 一致 |
| やや遠い(25%)+暗い+人が前を横切る | 0〜1/4(苦手) |
| 中間の角度(未登録) | 4/4 一致 |
| 右から(登録済み)/左から(未登録) | 2〜3/4 / 3/4 一致 |
| 別の看板 3 種・看板なし(誤検出チェック、計 16 回) | **誤検出 0** |

実際のカメラでは 1 秒に数回照合するため、1 回あたり 7 割程度の成功率でも、通常は 1 秒前後で見つかる。処理時間(PC): 1 回の走査 約 40〜100ms(特徴抽出 + 照合 1 件あたり 約 10ms)。

## トレードオフ・残存リスク

- 看板が画面の 1/6 未満・強い逆光・大きく遮られた状態は苦手 → 利用者には「近づいて画面いっぱいに」と案内する
- スマートフォン実機での速度・成功率は未計測(PC の 2〜4 倍遅い想定)。画像シンボルが数十件になると見つかるまでの時間が延びる
- 類似度判定をゆるめたぶん、低い周波数(大まかな明暗)が似た画像を偽造して API に送る攻撃の余地は QR より大きい。照合用パッチは非公開・結果は一致/不一致のみ・レート制限ありで抑止。重要なスポットは位置情報の現地確認も併用する
- 写真が SNS 等で出回ると遠隔で取得できる(QR と同じ)

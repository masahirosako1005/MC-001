# ADR 0007: コーデコンテスト

- 状態: 採用
- 日付: 2026-11-09

## 仕様と実装の対応

| 仕様 | 実装 (`contest/services.py`) |
|---|---|
| ① エントリー | `enter()`。アバターは**エントリー時点のスナップショット**(体のタイプ・肌・目・各パーツの形と色)を JSON で保存。後で着替えてもエントリーは変わらない。1 コンテスト 1 回(DB の一意制約)、開催期間中のみ |
| ② エントリー後は評価モード | エントリー完了後に評価画面へリダイレクト。エントリーしていない人は評価できない |
| ③ 3 体 × 3 回、各回 1 体まで高評価 | `current_round()` が 1 回分の候補を作り `EvaluationRound` に記録。`vote()` は表示した候補の中からのみ受け付け、1 回につき 1 体 (選ばないことも可)。同じ回への再送は最初の回答のまま (冪等)。回数・表示数は `Contest.rounds` / `per_round` で変更可 |
| ④ 表示回数が少ないアバターを優先 | `pick_candidates()`: 表示回数ごとの「層」に分け、少ない層から順に、層の中はランダム (`secrets.SystemRandom`) に選ぶ。同じ人の評価内では同じアバターを繰り返さない。候補を作るときはコンテスト行をロックし、表示回数の更新を直列化 |
| ⑤ 10 人までは BOT を含む / 10 人以上は BOT 非表示 / BOT への評価はランキングに反映しない | `bots_visible()` = 実参加者数 < `Contest.bot_cutoff`(既定 10)。BOT への高評価は記録には残すが `likes` に加算しない。ランキングは実参加者のみ |

## その他の決定

- **評価中は名前を出さない**(見た目だけで選ぶ公平性)。表示名はランキングでのみ表示し、空欄なら「旅人#1234」。本名を入れないよう案内(登録時のニックネームは他人に見せない約束のため、別の表示名にした)
- 自分のエントリーは候補に出さない。候補の並び順も毎回シャッフル
- BOT は管理画面のアクション「BOT を 12 体まで作成」または `seed_mikke` で作る。見た目は有効なパーツからランダム
- ランキングは高評価数の多い順、同数なら先にエントリーした順
- 不正対策: ログイン必須・CSRF・評価はサーバーが作った候補の中からのみ・他人の評価回には回答できない

## トレードオフ

- 後からエントリーした人は表示回数が少ないぶん優先して表示されるが、終了間際のエントリーは評価される機会が少ない
- 1 人が複数アカウントで自分に高評価を送る行為は、アカウント作成の制限 (メール確認など) が必要で未対応

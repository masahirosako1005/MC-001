### フェーズ 1: 正確性・データ完全性(コミット前に必須)

```
あなたは Django 6.1 アプリ「みっけ」(C:\AI-Sprint\workspace\MC-001)の開発者です。
現在の作業ツリーには未コミットの変更(クーポン管理機能・みっけ仲間機能)があり、以下の欠陥があります。
修正後は `DB_ENGINE=sqlite .venv\Scripts\python.exe manage.py test` と `python -m ruff check .` を全件成功させ、
可能なら PostgreSQL(`scripts\localdb.py start` 後、.env の既定設定)でも `manage.py migrate` と test を通してください。
既存の設計方針(サービス層 / ビュー層の分離、docs/requirements.md のトレーサビリティ表、ADR)を守ること。

1. rewards/migrations/0002_coupon_ids.py を 3 つのマイグレーションに分割する
   (a) AddField(null=True) のみ (b) RunPython でデータ移行 (c) AlterField で unique / null=False。
   理由: PostgreSQL では AddField→RunPython→AlterField を 1 トランザクションで行うと
   「cannot ALTER TABLE because it has pending trigger events」で失敗する。
   さらに、マイグレーションから rewards.models / rewards.services のライブコード
   (new_coupon_id, redeem_hash_of, new_redeem_code)を import しないこと。必要な関数は
   マイグレーションファイル内にコピーして固定する。

2. explore/manage_views.py の _coupons_for() と explore/forms.py の DropForm で、
   クーポン選択肢を「配布可能なクーポン OR そのフォームの instance が現在参照しているクーポン」にする。
   現状は配布停止・期限切れクーポンを参照する DropEntry があるとシンボル設定フォーム全体が
   「Select a valid choice」で保存不能になる。回帰テストを explore/tests_spots.py に追加する。

3. rewards/services.py の CouponNotDistributable を explore.services.ExploreError のサブクラスにするか、
   explore/services.py の collect() 内で捕捉して reward_kind="none" にフォールバックする。
   現状は explore/views.py api_collect で捕捉されず 500 になる。テストを追加する。

4. explore/forms.py CouponForm.save() で owner を設定するのは新規作成時(self.instance.pk is None)のみにする。
   現状は運営者が作った owner=None のクーポンを管理者が編集すると所有権が管理者に移る。

5. explore/services.py next_available_at() に now=None 引数を追加し、collect(now=) と同じ時刻を使う。

6. rewards/models.py の coupon_id は IntegrityError 時に再生成して再試行する
   (issue_coupon と同じ savepoint + リトライ方式)。

7. 有効期限の実効値(UserCoupon.expires_at と CouponTemplate.available_until の早いほう)を
   1 つの関数 effective_expires_at() に集約し、UserCoupon.status と use_coupon の両方から参照する。

8. accounts/migrations/0003 のグループ名「デモ利用者」を定数化し、seed コマンドと共有する。
```

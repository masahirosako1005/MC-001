# みっけ (Mikke)

**まちに隠れた「シンボル」をスマホのカメラでみっけして、アバターのコーデやお店のクーポンを集める、観光地の再訪を促す Web アプリ。**

季節・時間帯・訪問日数でもらえるコーデが変わるため、「一度行けば終わり」のスタンプラリーと違い、同じ場所に何度も来たくなる。
集めたコーデはきせかえ・コンテストで楽しみ、お店はクーポンで来店につなげ、運営は再訪率で効果を確かめる。

- 対象地域: 大阪府 京橋付近(地図データを同梱)
- 仕様の詳細: [設計書](docs/design.md) ・ 1 枚の概要: [概要](docs/overview.md) ・ 設計判断: [ADR 0001〜0015](docs/README.md)

## 1. 使う人と権限

| 権限 | 立場 | ログイン | 使う画面 |
|---|---|---|---|
| **利用者** | 観光客・地元の人 | 通常ログイン(自分で登録・自分で退会) | 利用者の画面(みっけ・きせかえ・コンテスト・クーポン・実績) |
| **管理者** | 店舗・会社の担当者 | 通常ログイン(サイト運営者が追加。最初のログインでパスワード変更) | **管理者コンソール** `/manage/` |
| **サイト運営者** | まち・サービスの運営者 | **専用のログイン画面**(URL は `.env` で秘匿) | **運営コンソール**・Django 管理画面 |
| だれでも | 通行人など | 不要 | トップ・ログイン画面のコーデとランキング・まちのサイネージ |

- 3 つの権限の画面とセッションは**完全に分けている**。管理者・運営者は利用者の機能を使えない(開くと自分の画面に戻る)。運営者のログインは専用の Cookie で、運営側の URL でしか有効にならない([ADR 0013](docs/adr/0013-console-separation-and-coupon-amounts.md))
- 管理者は**担当のスポット**とそのシンボル・自分のクーポンだけを扱える。運営者はすべてを扱える

## 2. 機能

### 2.1 利用者

**みっけ(探索)** — 地図とカメラを 1 画面で
1. 画面を開くと **①現在地を取得 → ②周囲のシンボルを検索**
2. 周囲(既定 100m、運営者が 10〜5000m で変更)にシンボルがあれば **「カメラでみっけ」** が押せる。なければ「ここにはなさそう・・・」と、いちばん近いスポットまでの距離
3. カメラ映像の中でシンボルを見つけると、位置に追従する光るマーク(疑似 AR)が出る。マーク(または同じ動作のボタン)を押して受け取る
4. 位置は判定にだけ使い保存しない。カメラ映像はサーバーに送らない

**シンボル** — 2 種類 + シークレット
- **QR シンボル**: 印刷して掲示する、中央に「み」ロゴ入りの QR
- **画像シンボル**: 看板・像・壁画など実物そのものが目印。管理者が撮影して登録(四角形の切り抜き・判定しない部分の塗りつぶし・最大 9 角度)。写した見え方が**類似度 65% 以上**なら反応([ADR 0005](docs/adr/0005-image-symbols.md))
- **シークレットシンボル**: 見つけるまで名前・ヒント・手に入るコーデを伏せ、地図では「？」だけ

**地図** — スポットは出さず、**シンボルだけ**を表示
- ★ 未みっけ / ✓ みっけ済み(次にみっけできる日時つき)/ ? 見つけていないシークレット。引いた表示では数字の丸にまとめる
- 印を押すと名前・スポット・ヒント。「近くのシンボルを探す」の結果は大きな★で、**そこで手に入るコーデの絵と条件**(季節・時間帯・訪問日数、いま出るか)
- 地図データはローカル配信(外部の地図 API なし。[ADR 0006](docs/adr/0006-local-protomaps.md))

**ごほうび** — 必ずコーデがもらえる(衣装全振り)
- シンボルごとのドロップ表から抽選。**季節・時間帯・解放に必要な訪問日数**の条件があり、同じシンボルでも来るたびに中身が変わる([ADR 0003](docs/adr/0003-revisit-design.md))
- 条件外・未設定でも「何もなし」にせず、ふだん用のコーデを渡す。持っているものは「取得済み」(コレクション回数が増える)。クーポンが出ることもある
- シンボルごとにクールダウン(既定 20 時間)

**結果画面**
- 手に入れた物の絵(アイテムは身につけた姿 + 部位の拡大図、クーポンはチケット型)、NEW / 取得済み、レア度、実績のごほうび
- レア度の横に **「こんな人も獲得しているよ」**: 同じコーデを直近 7 日に手に入れた人を 3 人
- 下に **「こんな人が獲得しているよ」**: 直近 30 分に同じ場所でみっけした人を最大 6 人
- 名前を押すとその人のコーデ、コーデを押すと**どこで手に入れたか**(スポットと季節)、スポット名から **「これをみっけに行く」** で地図に案内(**目印のシンボル名・ヒント・出る条件**つき)
- ほかの人として出るのは「みっけ仲間に表示する」を ON にした利用者だけ([ADR 0011](docs/adr/0011-recent-finders-and-coupons.md)・[ADR 0014](docs/adr/0014-public-ranking-and-signage.md))

**きせかえ** — ちびキャラのアバター([ADR 0004](docs/adr/0004-avatar-rendering.md))
- 体のタイプ(女の子 / 男の子、だれでも自由に選べる)、肌 8 色、目 6 色、顔・髪・トップス・ボトムス・くつ・こもの・エフェクト・背景の 8 部位
- パーツは 142 種類(女の子用 50・男の子用 50・共通 42。動くエフェクトあり)。持っているパーツだけ選べる

**コーデコンテスト**([ADR 0007](docs/adr/0007-contest.md))
- 今のアバターでエントリー → 3 体から 1 体を選ぶ評価を 3 回 → ランキング
- 表示回数の少ないアバターを優先。参加 10 人未満の間は BOT も出す(BOT への評価は数えない)。評価中は名前を隠す

**クーポン・実績・アカウント**
- クーポン: 1 枚ごとに重ならない引換コード(`MK-XXXX-XXXX`、暗号化保存)。店頭で「使う」を押すと使用済み(1 回だけ)
- 実績: 累計みっけ数・訪問スポット数・アイテム種類数・同じスポットの訪問日数・同じスポットで体験した季節数
- アカウント: ニックネーム、「みっけ仲間に表示する」、パスワード変更、退会(記録はすべて削除)
- UI テーマ 4 案(スタンダード / ゲームホーム / トラベルマガジン / 和モダン)を運営者が切り替え([ADR 0008](docs/adr/0008-ui-themes.md))

### 2.2 管理者(管理者コンソール `/manage/`)
- **ホーム**: 担当スポットの付近に来た人・カメラ起動・コーデ獲得(直近 30 日)、クーポンの使用枚数・**使用金額**
- **スポット**: 追加・編集・削除(地図で位置、判定半径、公開期間・無期限、現地確認の要否)。記録があるスポットは削除できず、非公開か期限切れにする
- **シンボル**: QR シンボルの追加と印刷、画像シンボルの撮影登録、名前・ヒント・クールダウン・シークレット・個別の位置、**ドロップ**(手に入るコーデ・クーポンと条件)
- **クーポン**: 登録・編集(タイトル・店舗名・特典・**1 枚あたりの金額**・利用条件・関連スポット・有効日数・有効期限・配布停止)。クーポン ID `CP-xxxxxx`
- **クーポンの実績**: クーポンごとの配布枚数・使用枚数・使用率・使用金額、月別グラフ
- **店舗・会社の情報**: 管理者 ID `MK-xxxxxx`、会社・店舗名、住所・電話(暗号化)。変更は運営者に依頼

### 2.3 サイト運営者(運営コンソール)
- **利用状況**: スポットごとの「付近に来た → カメラ起動 → コーデ獲得」、時間帯・季節別、管理者・期間で絞り込み
- **再訪率・アプリ利用率**: 再訪率(既定 30 日・1 年)、月ごとの再訪率、来た日数の分布、日ごとのアプリ利用率(直近 30 日)([ADR 0015](docs/adr/0015-revisit-rate-and-app-usage.md))
- **店舗ごとのクーポン利用**: 店舗ごとの配布・使用枚数・使用率・使用金額と棒グラフ。店舗を押すとクーポンごとの実績
- **まちのサイネージ**: ランキング 1 位のコーデ + 見出し + 宣伝の文 + サイトの QR コードを作り、プレビューを見ながら編集。表示用の URL(ログイン不要・推測できないキー・自動更新)をサイネージ端末のブラウザで開く。URL は作り直せる
- **利用者管理**: 一覧・検索、停止 / 再開、仮パスワードの発行。追加できるのは**管理者だけ**(利用者は自分で登録)
- **設定**: すべてのスポット・シンボル・クーポン(担当の管理者の割り当て)、アイテム一覧、サイト設定(UI テーマ・カメラを起動できる距離)

### 2.4 ログイン前の画面
- トップ(UI テーマ別、遊び方と写真風 CG)
- ログイン画面: **「いま、まちで手に入るコーデ」**(いまの季節・時間帯だけのアイテムを着た見本のアバター 3 体と手に入るスポット)と、**コンテストのランキング 1〜3 位**を、右から左へ流れる帯で表示(一時停止ボタンつき。動きを減らす設定では流さない)

## 4. 分析の指標

| 指標 | 定義 |
|---|---|
| 利用割合 | コーデを獲得した人 ÷ スポットの付近に来た人 × 100(人数は重複なし) |
| **再訪率** | 期間(既定 30 日)の中で「来た日」が 2 日以上の人 ÷ 1 日以上の人 × 100。**来た日 = みっけした日、またはクーポンを使った日**(同じ日は何回でも 1 日)。ログインしただけの日は数えない |
| **アプリ利用率**(日ごと) | その日にアプリを使った利用者(ログインだけも含む)÷ その日までに登録していた利用者 |
| クーポンの使用率 | 期間内に配った枚数のうち、使用済みになった割合 |
| クーポンの使用金額 | 使用枚数 × 使った時点の「1 枚あたりの金額」(あとで金額を変えても過去分は変わらない) |

数えるのは「利用者」だけ(管理者・運営者・停止中の人は除く)。グラフはすべて表でも確認できる。

## 5. しくみ

| 項目 | 内容 |
|---|---|
| サーバー | Python 3.13 / Django 6.1(画面はサーバーで組み立て + JSON API) |
| DB | PostgreSQL 17(TLS 1.3 必須・SCRAM 認証・データチェックサム)。SQLite でも動く |
| 配信 | nginx 1.28(HTTPS・静的ファイル)→ waitress(アプリ本体は 127.0.0.1:8080 だけで待ち受け) |
| フロント | テンプレート + 素の JavaScript(ビルドなし)。CSP で外部・インラインのスクリプトを禁止 |
| 読み取り | jsQR 1.4.0(QR)、jsfeat 0.0.8(画像の特徴点)。映像は端末内で処理 |
| 地図 | Leaflet 1.9.4 + protomaps-leaflet 5.1.0、PMTiles(京橋付近 約 4.2MB、© OpenStreetMap contributors) |
| 絵 | アバター・クーポン・グラフ・QR をサーバーで SVG として作る |

```
ブラウザ ──https://localhost:8000── nginx ──http://127.0.0.1:8080── waitress + Django ── PostgreSQL (TLS)
```

外部ライブラリは `static/vendor/` に同梱(npm の integrity 照合済み)。静的ファイルは名前に内容のハッシュを付けて配信し、更新するとすぐ届く。

## 6. セキュリティ・プライバシー

- **暗号化**: メール・住所・電話番号・引換コードは AES-256-GCM で暗号化して保存(照合は HMAC のブラインドインデックス)。パスワードは Argon2・15 文字以上([ADR 0002](docs/adr/0002-db-encryption.md))
- **通信**: nginx で TLS 1.2 / 1.3(localhost 専用の自己署名証明書。認証局としては使えない)。`X-Forwarded-For` は nginx が上書きし、偽装できない([ADR 0012](docs/adr/0012-local-https-reverse-proxy.md))
- **認証**: ログインの失敗はアカウント 5 回 / IP 20 回で 15 分ロック(運営者ログインはより厳しく、セッション 4 時間)。仮パスワードは最初に変更を強制
- **権限**: 画面とセッションを権限ごとに分離。他店のデータは開けない(404)。運営画面の URL は秘匿し、存在も見せない
- **不正な受け取りの防止**: 署名付きチケット(利用者に結び付き 5 分)、現地確認、移動速度のチェック、二重送信防止、クールダウン、レート制限。クーポンは 1 回だけ使える
- **位置・映像**: 位置は判定にだけ使い保存しない(URL にも載せない)。カメラ映像は送らない
- **公開の画面**: ほかの人の名前を出すのは本人が「みっけ仲間に表示する」を ON にしているときだけ(結果画面・ログイン画面・サイネージ)。ほかの人のコーデは見る人に結び付いたランダムな ID でしか開けない
- **記録**: アプリの利用は日付だけ。監査ログ(ログイン・設定変更・権限操作・退会など)は追記専用で、IP はハッシュ
- **画面**: CSP(`'self'` のみ)、自動エスケープ、SVG はサンドボックス、エラー画面は日本語の独自ページ

## 7. セットアップと起動

前提: Windows、Python 3.12 以上、PostgreSQL 17 のバイナリ(`%LOCALAPPDATA%\pg17`)、nginx for Windows(`%LOCALAPPDATA%\nginx-1.28.0`)。

### 7.1 初回だけ

```bash
python -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

```bash
.venv\Scripts\python.exe scripts\localdb.py init
```

`init` は `.env` に秘密値をランダムに作り、PostgreSQL を初期化(TLS 証明書・`hostssl` のみ・SCRAM)してアプリ用のロールと DB を作る。

```bash
.venv\Scripts\python.exe manage.py migrate
```

```bash
.venv\Scripts\python.exe manage.py seed_mikke
```

```bash
.venv\Scripts\python.exe manage.py createadmin --email ops@example.com
```

`.env` に次を書く(HTTPS で本番相当に動かす設定): `DJANGO_DEBUG=0`、`DJANGO_BEHIND_TLS_PROXY=1`、`DJANGO_SSL_REDIRECT=1`、`DJANGO_SECURE_COOKIES=1`、`DJANGO_HSTS_SECONDS=0`、`MIKKE_TRUSTED_PROXIES=127.0.0.1`、`MIKKE_CACHE=db`(見本は `.env.example`)。

### 7.2 起動・停止

```bash
start.bat
```

PostgreSQL の起動 → 接続の確認 → 未適用のマイグレーションの適用 → 静的ファイルの収集 → nginx → アプリ を順に行う。`https://localhost:8000` を開く。止めるときは Ctrl+C か次のコマンド(PostgreSQL も止めるなら `--with-db`)。

```bash
stop.bat
```

- 状態の確認: `.venv\Scripts\python.exe scripts\serve.py status`(PostgreSQL・アプリ・nginx・証明書の登録)
- PC を再起動したあとも `start.bat` だけで動く。PostgreSQL は起動したウィンドウを閉じても止まらない
- 開発で HTTPS なしに動かすときは `.env` を `DJANGO_DEBUG=1` にして `manage.py runserver`

### 7.3 証明書の信頼登録(ブラウザの警告を消す)

証明書は起動時に自動で作られ、プロジェクトの `certs\localhost.crt` に書き出される(秘密鍵は書き出さない。`certs/` はコミットしない)。システムの設定変更なので各自で実行する(確認の画面で「はい」)。

```bash
certutil -user -addstore Root "certs\localhost.crt"
```

登録できたかは `scripts\devproxy.py trust` で確認(「信頼: 登録済み」)。登録後はブラウザのウィンドウをすべて閉じて開き直す。証明書を作り直した(`devproxy.py cert`)ときは登録し直す。

### 7.4 デモデータ(開発用。`DJANGO_DEBUG=1` のときだけ実行できる)

| コマンド | 内容 |
|---|---|
| `seed_mikke` | 初期データ: アイテム 142 種類・スポット・シンボル・クーポン・実績・コンテスト |
| `seed_analytics` | 分析用: 架空のスポット 100・管理者 12・行動 1 年分・クーポン。確認用アカウント `manager@test.com` / `user@test.com` も作る(仮パスワードは実行のたびに 1 度だけ表示) |
| `seed_engagement` | 再訪率の確認用: 利用者を 10,000 人に増やし、1 年分のアプリ利用(約 40%)・みっけとクーポン利用(1 年の再訪率 約 20%)・コンテスト(約 1,000 人)を作り直す |
| `link_item_symbols` | 持ち物に「手に入れたシンボル」を結び付ける(シードの最後に自動で実行) |

確認用のアカウントは本番 DB に残さない(`manage.py check --deploy` が検出する)。

### 7.5 公開・本番の前に
- `DJANGO_DEBUG=0` にする(DEBUG のままだとエラー画面に内部の URL 構成が出る。DEBUG 中は画面上部に警告帯)
- 複数のプロセスで動かすときは `MIKKE_CACHE=db` か `redis://…`(ロック・レート制限・みっけ仲間の ID を共有するため)
- プロキシの内側で動かすときは `MIKKE_TRUSTED_PROXIES` にプロキシの IP / CIDR
- 運営画面・管理画面の URL を推測されにくい値に、問い合わせ先を `MIKKE_SUPPORT_CONTACT` に
- スマホから使うには、公開する HTTPS の URL と証明書が必要(いまの nginx は 127.0.0.1 だけで待ち受ける)

## 8. 設定と管理コマンド

主な設定(`.env`、見本は [.env.example](.env.example)):

| 変数 | 内容 |
|---|---|
| `DJANGO_DEBUG` / `DJANGO_SECRET_KEY` / `DJANGO_ALLOWED_HOSTS` | 基本設定 |
| `DJANGO_ADMIN_URL` / `MIKKE_OPS_URL` / `MIKKE_OPS_SESSION_SECONDS` | 管理画面・運営画面の URL、運営者のログイン時間(既定 4 時間) |
| `MIKKE_FIELD_KEYS` / `MIKKE_BLIND_INDEX_KEY` | 暗号鍵(必須。`localdb.py init` が作る) |
| `DB_ENGINE` / `DB_*` / `PG_BIN` / `PGDATA` | PostgreSQL(または `sqlite`) |
| `DJANGO_BEHIND_TLS_PROXY` / `DJANGO_SSL_REDIRECT` / `DJANGO_SECURE_COOKIES` / `DJANGO_HSTS_SECONDS` | HTTPS 関係 |
| `MIKKE_CACHE` / `MIKKE_TRUSTED_PROXIES` / `MIKKE_LOGIN_MAX_FAILURES_PER_IP` | キャッシュ・プロキシ・IP 単位のロック |
| `MIKKE_SUPPORT_CONTACT` | 「パスワードを忘れた方」の問い合わせ先 |
| `MIKKE_MAP_BOUNDS` / `MIKKE_MAP_CENTER` / `MIKKE_MAP_TILES` | 地図の範囲・タイル |
| `NGINX_HOME` / `MIKKE_PROXY_DIR` / `MIKKE_PROXY_PORT` / `MIKKE_APP_PORT` / `MIKKE_CERT_EXPORT` | nginx・ポート(8000 / 8080)・証明書の書き出し先 |

カメラを起動できる距離と UI テーマは、運営コンソールの「サイト設定」で変える。

その他の管理コマンド: `createadmin`(サイト運営者の作成)、`contest_reset_entry`(コンテストのエントリーを外す)、`scripts\localdb.py start|stop|status`(PostgreSQL)、`scripts\devproxy.py start|stop|status|cert|trust`(nginx と証明書)。

## 11. 制約・今後の課題
- 地図データは京橋付近だけ。実機スマホでのカメラ検出・GPS の精度は未計測(スマホから使うには公開用の HTTPS が必要)
- 分析はその場で集計(利用者 1 万人・1 年分で 1 秒以内)。規模が大きくなったら日ごとの集計テーブルにする
- 画面は日本語のみ。パスワードを忘れたときは運営者が仮パスワードを発行する(メール送信の仕組みはない)
- アプリの利用日 (DailyActivity) は 1 人 1 日 1 行で増え続けるため、長期運用では古い日を月ごとの集計に置き換える

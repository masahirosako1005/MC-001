# ADR 0013: 利用者 / 管理者 / サイト運営者の画面とセッションの分離、クーポンの使用金額

- 状態: 採用
- 日付: 2026-11-10

## 背景
- サイト運営者として運営者専用の画面からログインしたまま、利用者の画面 (きせかえ・みっけ など) に入れてしまっていた。セッションは 1 つだけで、運営者の権限を持つ Cookie がすべての画面で使われていた
- 管理者がログインした直後も利用者と同じ画面で、店舗の担当者として何をすればよいか分かりにくかった。運営者も右上のメニューから利用者の機能を使えた
- 分析で、店舗ごとに使われたクーポンの枚数と金額を見たい。クーポンの情報は店舗の管理者にも見せたい
- クーポンは特典の文章 (例: 「ドリンク 50 円引き」) しか持たず、金額を数えられなかった

## 決定

### セッションの分離 (core/sessions.py)
- `RealmSessionMiddleware` が Django の SessionMiddleware の代わりに働き、URL によって読む Cookie を変える
  - **運営側** (`MIKKE_OPS_URL` と `DJANGO_ADMIN_URL` の下): `mikke_ops_session` だけを読む
  - **利用者側** (それ以外): ふつうのセッション Cookie だけを読む
- 運営者のログインは運営側の Cookie にだけ入るので、利用者の画面では「ログインしていない」状態になる。逆に、利用者・管理者のログインでは運営側に入れない。同じブラウザで両方に別々にログインしておくこともできる
- 運営側のセッションに運営者以外がいたら、また利用者側に運営者のログインが残っていたら (以前の版のもの)、ログアウトさせる (`RoleAreaMiddleware`)
- 運営者のログアウト・パスワード変更・仮パスワード後の強制変更も運営側に置く (`ops:logout` / `ops:password_change`)
- Cookie のパスはどちらも `/` (運営側は 2 つの URL の下にあるため)。運営側の Cookie は利用者側にも送られるが読まれない

### 画面の分離
- **管理者**: ログインすると管理者コンソール (`/manage/`) に入る。利用者の画面 (ホーム・きせかえ・みっけ・コンテスト・クーポン・アカウント・退会) を開くと管理者のホームに戻す (API は 403 JSON `wrong_area`)。使えるのは管理者の画面・ログアウト・パスワード変更だけ。遊ぶときは利用者として別のアカウントを登録する
- **サイト運営者**: 運営コンソール (運営者の URL の下) で、分析・店舗ごとのクーポン利用・利用者管理・スポット / シンボル / クーポンの設定・アイテム一覧・サイト設定を使う
- 設定画面 (スポット・シンボル・クーポン) は、同じビューを 2 か所に置く (`explore/manage_urls.py`)
  - `/manage/` … インスタンス名前空間 `manage` (管理者、利用者側のセッション)
  - `/<運営者の URL>/manage/` … インスタンス名前空間 `ops_manage` (運営者、運営側のセッション)
  - テンプレートの `{% url 'manage:…' %}` は表示中の側の URL になる (Django の current_app)。ビューでは `core.permissions.manage_url()` を使う
- コンソールは `templates/console/base.html` と `static/css/console.css`。左メニュー (狭い画面では横 1 行) と、管理者は青緑・運営者は藍色のヘッダーで利用者の画面と見分けられる。メニューは `core/console.py` で組み立て、利用者の機能へのリンクは置かない
- パスワード変更など両方で使う画面は `base_template` (コンテキストプロセッサ `core.context_processors.console`) を継承し、管理者・運営者にはコンソールの見た目で出す

### 廃止したもの
- 利用者の画面での UI テーマの「自分だけ試す」(`?ui=`)。運営者は利用者の画面を開けないため。テーマの切り替えは従来どおり「サイト設定」で、見え方は利用者のアカウントで確認する
- きせかえの「管理者モード」(運営者が全パーツを選べる)。パーツの確認は運営コンソールの「アイテム一覧」(`ops:item_catalog`) で行う

### クーポンの使用金額 (rewards/stats.py)
- `CouponTemplate.value_yen`「1 枚あたりの金額 (円)」(0〜1,000,000、空欄は 0)。割引率のクーポンは平均的な値引き額で換算して登録する
- 使った時点の金額を `UserCoupon.used_value_yen` に記録する (使用の条件付き UPDATE と同時)。あとから金額を変えても過去の使用金額は変わらない
- 指標 (期間: 直近 7 / 30 / 90 / 365 日・全期間)
  - 配布枚数: 期間内に配った枚数 / 使用枚数: 期間内に使われた枚数 / 使用金額: 期間内に使われた分の `used_value_yen` の合計
  - 使用率: 期間内に配った分のうち使用済みの割合
- 店舗 = クーポンを登録した管理者。登録者がいなければ関連スポットの担当の管理者。どちらもなければ「サイト運営者」
- 管理者: 「クーポンの実績」で自分のクーポン (自分で登録したもの・担当スポットのもの) のクーポンごとの実績と月別 (直近 12 か月) の使用枚数・金額のグラフ。ホームにも直近 30 日の合計を出す
- 運営者: 「店舗ごとのクーポン利用」で店舗ごとの実績と上位 15 店舗の棒グラフ。店舗名からその店舗のクーポンごとの実績へ (`owner` の絞り込みは運営者だけ)
- 枚数と金額は単位が違うので、1 つのグラフに 2 軸で描かず、別のグラフにする

## 結果
- 運営者の権限を持つ Cookie は運営側でしか使われず、利用者の画面からは運営者の機能にも、運営者のまま利用者の機能にも届かない
- 管理者・運営者は、ログイン直後から自分の役割の画面で作業できる
- 店舗ごと・クーポンごとに、使われた枚数と金額を比べられる。金額は管理者が登録した換算値なので、実際の売上や値引き額とは一致しないことがある
- 既存のクーポンは金額 0 円から始まる。金額を設定したあとに使われた分から数える
- 運営者 Cookie のログインで CSRF トークンが入れ替わるため、同じブラウザで開いていた利用者の画面のフォームは、一度読み込み直すまで送信できないことがある
